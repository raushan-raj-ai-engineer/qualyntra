# Artifact Storage

Qualyntra stores screenshots, traces, videos, logs, reports, prompts/model outputs, and other evidence behind a vendor-neutral `ArtifactStorageAdapter`. Artifact metadata is separated from object bytes so the control plane can use different catalog and object-store implementations without changing execution or reporting contracts.

## Security and integrity rules

- Storage keys are generated by Qualyntra and are opaque; user filenames never become object paths.
- Tenant scope is represented in storage keys by a one-way digest rather than raw organization/project identifiers.
- Every upload is SHA-256 hashed while its stream is consumed, and size limits are enforced during streaming.
- Empty artifacts are rejected.
- Downloads can be streamed through `downloadVerified`, which fails closed if size or SHA-256 differs from recorded metadata.
- Artifact metadata is recursively redacted before catalog persistence.
- Remote object stores remain subject to the existing outbound network policy.
- Download grants are time-bounded, HTTPS-only (except explicitly allowed localhost development), audited, and never persisted in artifact metadata.
- Raw cloud credentials are not part of `ArtifactRecord` or any storage-key contract.

## Retention

Each artifact can inherit a configured default retention period, request an allowed shorter/longer period, or explicitly use retention `0` for no automatic expiry where policy allows. `sweepExpired` deletes object bytes first and removes metadata only after the storage adapter reports success. Failures are counted and retried by the caller rather than silently losing catalog state.

## Local storage

`artifact.local` is the reference development/on-prem adapter. It:

- confines generated keys beneath a configured root;
- creates objects without overwrite (`wx` semantics);
- writes private `0600` object/metadata files;
- cleans only files created by the current failed write;
- supports streaming reads/writes;
- intentionally does not issue transferable download URLs.

It is not intended to replace enterprise object storage for horizontally scaled deployments.

## S3-compatible storage

`artifact.s3` is SDK-neutral. A deployment supplies an `S3ArtifactClient` that owns credentials/signing and implements put/get/head/delete/presign operations. Qualyntra does not embed access keys, vendor SDKs, bucket names, endpoints, or pricing. Time-limited download grants map naturally to S3 presigned GET URLs.

## Azure Blob storage

`artifact.azure-blob` is also SDK-neutral. A deployment supplies an `AzureBlobArtifactClient`. The recommended production implementation uses Microsoft Entra/managed identity and user-delegation SAS for time-limited reads rather than persisting storage account keys in Qualyntra.

## Scale path

The contracts support future PostgreSQL-backed artifact catalogs, multipart/object-store streaming, WORM/legal-hold policies, KMS/BYOK encryption metadata, malware/content scanning, signed provenance, and CDN/download brokers without changing evidence producers.
